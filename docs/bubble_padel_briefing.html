🔄 5. Fluxo do Torneio — Estado Atual

O ciclo de vida completo implementado, com as decisões tomadas ao longo do desenvolvimento.

DRAFT → PUBLISHED → OPEN → CLOSED → ONGOING → COMPLETED

✓ Transições manuais

Clube controla: publicar, abrir inscrições, encerrar inscrições, reabrir, finalizar torneio.

✓ Transições automáticas

ONGOING: quando primeiro placar de grupo é salvo. COMPLETED: quando todos os jogos de playoff são jogados.

⚠ Falta implementar

ONGOING por data/hora: torneio muda automaticamente quando a hora do primeiro jogo chega. Requer cron job ou trigger no backend.

O que está sólido e o que precisa ser resolvido antes de escalar para múltiplos clubes simultâneos.

  • Upserts seguros com Prisma (sem duplicatas)
  • API pública separada da autenticada

💰 8. Monetização — Modelo Definido ✅

Modelo de comissão por atleta definido na Sprint 3. Split de pagamento planejado quando AbacatePay lançar o recurso. Durante o lançamento: R$0 de comissão ("Grátis durante o lançamento").

✅ Decisão final — Modelo B: Comissão por atleta via split

  • Valor: R$3,00 por atleta inscrito (configurável via COMMISSION_PER_ATHLETE)
  • Mecanismo: Split de pagamento — AthleteR$120 → R$115 clube + R$3,50 Bubble + taxa gateway
  • Status split: AbacatePay em desenvolvimento — ativar quando lançar
  • Lançamento: R$0 de comissão ("Grátis durante o lançamento")
  • Infra pronta: COMMISSION_PER_ATHLETE=0, model Reconciliation, email de relatório ao clube

Modelo A — SaaS B2B (Clube paga)

Clube paga mensalidade para usar a plataforma. Atletas inscrevem-se gratuitamente. Simples de implementar, previsível.

✓ Receita previsível (SaaS)
✓ Fácil de vender para clube
✗ Clube precisa de volume de torneios
✗ Difícil cobrar R$X/mês sem histórico

Modelo B — Comissão por inscrição (RECOMENDADO)

Bubble cobra X% ou R$Y por atleta inscrito. O clube recebe o restante. Zero custo para clube começar. Bubble cresce junto com o sucesso do clube.

✓ Zero barreira de entrada (PLG)
✓ Bubble ganha escala naturalmente
✓ Alinhamento de incentivos
⚡ Requer gateway de pagamento

Modelo C — Freemium + Features Premium

Torneios básicos grátis. Features avançadas (custom branding, analytics, múltiplos organizadores) no plano pago.

✓ Fácil de adotar
✗ Difícil convencer a pagar sem histórico
✗ Features premium ainda não existem
📋 Decisão Pendente (Alta Prioridade)

O modelo B (comissão por inscrição) é o mais recomendado pelos especialistas para o lançamento: elimina a barreira de entrada, alinha os incentivos e permite crescimento orgânico. Estimativa: R$2-5 por atleta inscrito (torneio médio de 30 duplas = 60 atletas = R$120-300 por torneio). Um clube com 2 torneios/mês = R$240-600/mês para a Bubble.

Growth / Aquisição

"Cobrar mensalidade do clube antes de provar valor é o maior erro de PLG. Comissão faz a Bubble crescer junto com o clube — zero custo para começar, todos ganham ao mesmo tempo."

Sports Tech Benchmarking

"PlayTomic cobra comissão de 15-20% por reserva. No Brasil, 5-8% por inscrição é competitivo e aceitável para clubes de padel premium."

🚀 11. Estratégia de Lançamento

Lançamento em 3 fases com critérios claros de go/no-go. Começar pequeno, validar, escalar.

Fase 1 — Alpha (2-3 semanas)

1-2 clubes conhecidos. Torneio real mas gratuito (sem cobrança). Foco em estabilidade e bugs. Feedback intensivo do organizador.

  • ✦ Termos de uso publicados
  • ✦ Email de confirmação funcionando
  • ✦ Fluxo completo sem erros

Fase 2 — Beta Fechado (4-6 semanas)

5-10 clubes. Primeiro torneio com pagamento real de inscrição. Modelo de comissão ativo. NPS ≥ 7.

  • ✦ Gateway de pagamento integrado
  • ✦ Notificações funcionando
  • ✦ Suporte direto aos organizadores

Fase 3 — Lançamento Público

Landing page no ar. Cadastro self-service para clubes. Marketing ativo. Meta: 20 clubes ativos no primeiro mês.

  • ✦ NPS ≥ 7 no beta
  • ✦ Zero bugs críticos em 2 semanas
  • ✦ Pelo menos 3 torneios completos

🎯 15. Resumo Executivo

🚫 Top 4 Bloqueadores de Launch
1. Sem termos legais — Coleta dados pessoais sem LGPD. Não pode operar comercialmente.
2. Sem email transacional — Atleta se inscreve e não recebe confirmação. Churn silencioso.
3. Sem modelo de monetização ativo — Produto está pronto mas não gera receita ainda.
4. Sem onboarding de clubes — Novo clube entra e não sabe o que fazer primeiro.
⚡ Top 5 Quick Wins
1. Share button + OG tags — 4h de trabalho. Viral loop imediato na página pública.
2. Email de confirmação — 4-8h com Resend. Primeiro passo de retenção do atleta.
3. Rate limiting nas rotas públicas — 2h. Protege contra spam de inscrições.
4. ONGOING automático por data — 4h. Remove fricção do organizador.
5. Checklist de onboarding do clube — 6h. Melhora ativação de novos organizadores.
